## 5. Group B decision pack (approval required, not implemented)

Each decision gives the existing behaviour, the proposed behaviour, the evidence, the false-TRADE and false-suppression risks, the tests, and my recommendation.

### 5.1 Interval-aware candle-age grace (investigation option 1)

- **Existing:** no candle-age check; a 2 h 15 min old completed bar during OPEN gives TRADE (scenario C).
- **Proposed:** the last completed bar's close must be within one interval plus a grace (15m interval).
- **Evidence:** scenario C and E produce TRADE today.
- **Before/after:** C → NO TRADE; A1 (completed 0 min ago) → TRADE; B (completed 30 min ago, beyond 15 min + 2 min) → NO TRADE.
- **False TRADE risk:** removed for stale bars.
- **Suppression risk:** a bar is legitimately up to one interval old, and the grace value sets how much feed lag is tolerated. A grace below about 2 minutes would block valid bars at the bar boundary.
- **Tests:** boundary at the grace value; scenarios A1, B, C, E.
- **Recommendation:** a 15-minute interval with a **grace of 2 minutes** (bar-boundary lag). The 2-minute figure is my proposal, not an existing constant. The existing 300 s rule must not be reused on the bar close, because it would block most of each bar's life.

### 5.2 Completed-bars-only indicator inputs (investigation option 2)

Comparison run offline, same 16 scenarios, with and without bars whose interval has not closed:

| Scenario | Price | Indicators changed | Engine decision |
|---|---|---|---|
| A1 (no forming bar) | unchanged | none | TRADE → TRADE |
| A2 (forming 12:30 bar) | 22171.65 → 22165.30 | EMA9 22140 → 22132, EMA21, EMA50, VWAP, RSI 81.6 → 80.7, MACD histogram 8.7 → 9.2 | TRADE → TRADE |
| E (forming bar on a 2 h gap) | 22076.14 → 22070.49 | EMA9 22034 → 22024, EMA21, EMA50, VWAP, RSI 64.0 → 62.7, **MACD histogram 0.68 → −3.40 (sign change)** | TRADE → TRADE |
| L (first bar only, 09:20) | 22070.49 → 21985.00 | EMA9, EMA21, EMA50, VWAP 22068.95 → 22036.92, **RSI 62.7 → 26.3**, MACD histogram −3.4 → −9.0, ATR, prior-day levels, opening range | **WAIT → NO TRADE**, with a "Market closed" message |
| B, C, D, F, G, H, I, J, K, M, N | unchanged | none | unchanged |

- **Existing:** the forming bar's close is the price and is in every indicator (`technicalAnalysis.ts:197–198`).
- **Proposed:** drop bars whose interval has not closed before indicators.
- **Findings:**
  - Indicators move, sometimes sign-flipping (E). The fixtures are synthetic, so real-market magnitude is unknown.
  - The engine decision stayed TRADE in A2 and E, so the fixtures do not show decision flips here.
  - **At the open (L), the rule removes the only current-session bar and then reports "Market closed"**. That is a real regression: NO TRADE should be WAIT with the opening-window reason. It would need an opening-window fix alongside.
- **False TRADE risk:** reduced, because indicators no longer use an incomplete bar.
- **Suppression risk:** the first 15 minutes of a session would show "Market closed" unless fixed; this needs the opening-window case handled first.
- **Recommendation:** approve the rule **together with** a fix for the opening case, so that a session with only incomplete bars is reported as "waiting for first completed bar", not "market closed". That message fix is itself a Group B decision (new text or code, §5.5).

### 5.3 Dropped-bar policy (malformed or invalid latest bar)

- **Existing:** a malformed or invalid latest bar is dropped silently; the series then ends an interval earlier (scenarios F1, F2: the last bar becomes 12:00 and TRADE is still permitted, with no signal).
- **Options:**
  - (a) Keep as is (silent).
  - (b) Count dropped bars and report them in the diagnostic, without changing eligibility.
  - (c) Treat a dropped **latest** bar as UNKNOWN: no TRADE for that cycle.
- **Recommendation:** (c) for the latest bar only. A dropped latest bar means the feed has a gap at the moment of decision. Option (b) for older bars. This changes eligibility in F1 and F2, so it needs your approval.

### 5.4 Closed-session source label (investigation option 5)

- **Existing:** closed-session candles (J: bars to 15:15 on a closed day; M, N: weekend and holiday history) carry the source label LIVE. Technical factors are then unavailable only because the market source is END_OF_DAY (source mismatch, `analysis.ts:212–213`). The diagnostic then reports "insufficient technical data".
- **Proposed:** label closed-session technicals END_OF_DAY.
- **Interaction risk (checked against code):** factor availability requires source equality. With the market END_OF_DAY and technicals END_OF_DAY, the technical factors **become available on end-of-day data**. The engine still returns WAIT or NO TRADE in closed sessions (`isEod` in `strategy.ts`, and the staleness blocker at `strategy.ts:173–174`), so no TRADE follows. But candidates, factor values and diagnostic blocker codes would change.
- **Recommendation:** approve only after a dedicated analysis showing the closed-session outputs. I have not run that analysis; it is the next step if you want this decision made.

### 5.5 Pre-open and no-intraday messages (Defect E)

- **Existing:** pre-open and open-with-no-bars (D, K) say "Market closed: latest candles are from <previous session>" with the END_OF_DAY code. This is fail-closed (NO TRADE) but misleading.
- **Constraint:** the text is generated in `strategy.ts:184`, which is frozen. A correction is possible only diagnostic-side, and that would add or rename a public blocker code. The B4 policy asked me to stop and report before adding one.
- **Recommendation:** approve a new diagnostic code for "no intraday bars yet" (for example `NO_INTRADAY_CANDLES`), mapped from the engine text in `recommendationDiagnostic.ts` only. Engine decisions stay unchanged.
