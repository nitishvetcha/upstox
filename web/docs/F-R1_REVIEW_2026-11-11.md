# F-R1 review (stage D): missing EMA 200 can still yield an unqualified TRADE

Status: review complete. No change made to the frozen strategy (`src/lib/engine/strategy.ts`, SHA-256 d0170b40…).

## What happens today
- `src/lib/engine/analysis.ts` (around lines 29–31): when EMA 200 is null, the "EMA 50 vs EMA 200" trend factor is left without its vote. The factor is not marked unavailable, and no blocker is raised.
- The remaining factors can still produce a TRADE. The test `F-R1` in `src/lib/recommendationPipeline.test.ts` expects no unqualified TRADE and is skipped.
- Real data: EMA 200 needs at least 200 candles on the timeframe. Early in a session or on short histories it can be null, so this path is reachable in live use.

## Options
1. **Blocker in the recommendation layer (favourite).** When EMA 200 is null, add a blocker that forces WAIT (or NO TRADE) and no plan. The frozen strategy file is not touched. Outputs change only in the case where EMA 200 is missing. Unskip F-R1.
2. **Mark the trend factor unavailable inside the engine.** Consistent with how other missing inputs are handled, but changes engine code near the frozen rules. Needs explicit change control.
3. **Accept the behaviour and document it.** Not recommended: the test records it as a defect.

## Evidence needed before a GO decision
- Option 1 or 2 must be implemented under change control, with before/after outputs for the mock and fixture cases.
- No validated out-of-sample evidence exists in this repository. P1 is rejected, the holdout is sealed, and no new backtests are authorised. A GO decision therefore cannot be reached by code changes alone.

## Recommendation
Approve option 1 as a separate change. Keep the recommendation engine NO-GO until validated evidence is produced under a new, owner-approved protocol.

## Update: the fix applied (root cause corrected)

- **Root cause (corrected):** the trend factor was still *available* when EMA 200 was missing, scored on three votes. The engine's rule that blocks trades when a factor is unavailable therefore never fired.
- **Fix (applied):** `src/lib/engine/analysis.ts` marks the whole trend factor unavailable when EMA 200 is null. The engine's existing missing-factor rule then blocks the trade. This is better than the blocker in the recommendation layer, because it uses the rule the engine already has for every other missing input.
- **Frozen strategy:** `src/lib/engine/strategy.ts` unchanged (SHA-256 d0170b40…).
- **Mock outputs:** identical before and after (mock data always includes EMA 200).
- **Tests:** F-R1 unskipped and passing. Pipeline tests 15/15. Full suite 2,727 tests, 2,727 pass, 0 fail, 0 skipped.
- **Remaining for a GO decision:** validated out-of-sample evidence under a new owner-approved protocol. The F-R1 defect itself is no longer open.
